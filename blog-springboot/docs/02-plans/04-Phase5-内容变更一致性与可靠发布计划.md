## 实施与验收原则

先复用已有 MySQL、Redis、RabbitMQ、ES、任务表；不预设新增Outbox平台或分布式事务框架。提交后通知不能单独证明可靠投递，先读后改状态不能证明原子幂等，删缓存不能单独证明多实例一致性。

验证覆盖被修改切片的正常、失败、恢复与重复/乱序/并发场景，选择其中实际相关的路径。使用受控故障和并发屏障，优先无需真实业务数据和付费模型的隔离验证。不全量压测、不扫描生产库、不编造性能数字。必须把单测、依赖联调与真实业务运行分开报告。

若涉及迁移，先核实目标元数据并提供可审阅SQL；沿用既有数据操作授权边界。不修改用户已有ArticleController变更，不推送、部署或合并。

## 首个切片：批量搜索同步的失败与恢复（BD-004）

业务不变量：一条文章 CDC 消息中的有效行完整同步；任何一行失败都不能当作整条成功；重复或人工重放不能因 UPDATE 文档不存在而永久失败，也不能照搬消息里的旧正文。消息仅携带变更提示，正文和 PUBLIC/isDelete 状态从 MySQL 当前行读取；物理删除、私密、草稿或软删除从 ES 移除。按 ID 全文索引覆盖，删除不存在的文档视为成功。

方法与文件：ArticleConsumer 校验文章表、多行 ID 后逐条调用 ElasticsearchService.syncArticle；ElasticsearchServiceImpl 回源当前文章并 upsert/delete，失败向上传递；专用 ArticleSearchSyncConfig 配置 AUTO ACK、每次投递最多3次处理、3秒间隔、带 publisher confirms/returns 的原始消息故障转存。确认故障队列接收后才能结束原消息，转存失败重新入队。RabbitMqConfig 仅增加故障交换机/持久队列/绑定，不修改已有 article.queue 参数，避免已有队列重声明冲突。CanalDTO.es 修正为 Long 以承接13位时间戳，但不把它用作内容版本。无需数据库表变更，不添加运营平台或定时全库扫描。

验证：针对多行、部分失败后整批重放、旧事件读取新数据库状态、草稿/私密/软删除/物理删除、ES失败传播、故障转存失败保留原消息进行隔离验证。使用实际 Spring Retry 拦截器验证重试次数与恢复边界，不运行付费模型和真实服务写入。

限制：回源当前行降低旧事件重放风险，但读取与写入之间仍可遇到跨实例并发，不等价于版本化写入。私人标签规则、公开查询的实时权威校验、ES refresh 延迟、历史漏同步修复仍属于后续 BD-001/004 内容。本轮不宣称整个发布/撤回链路闭环。

## 第二个切片：公开详情与搜索的撤回读取屏障（BD-001）

2026-10-17 实施范围：仅依据明确的 `status=PUBLIC(1)` 且 `is_delete=0` 判断当前是否仍可公开；不将私人标签、类别和特定账号规则合并成未经确认的新权限模型。保持现有私人筛选，另行记录其不一致。

详情在取得缓存/回源内容之后、增加浏览统计及输出之前，按文章主键进行不走内容缓存的数据库状态校验；校验不通过按现有未找到契约返回 null，不返回标题、正文、AI摘要。搜索在策略执行后、返回 HTTP 调用方前，对候选主键一次批量校验，保留候选顺序与原高亮，仅返回当前公开且未删除的记录。状态查询失败直接失败，不降级输出旧内容；ES故障不再伪装成空结果。上一篇/下一篇的现有查询已按公开且未删筛选，保持查询行为。

实现入口：ArticleMapper 新增只返回允许主键的查询；ArticleServiceImpl.getArticleHomeById 使用 singleton 集合校验；SearchStrategyContext 在 MySQL/ES 两种策略共同出口过滤；EsSearchStrategyImpl 传播明确服务失败。没有数据库字段变更、新中间件或配置项。Search.vue 仅配套承接业务失败/网络失败及重试，始终保持数组并丢弃过期响应，避免失败响应的 null 破坏结果列表。

业务承诺：撤回事务已提交且在本次权威状态 SQL 快照中可见时，旧缓存/旧索引不能单独决定返回文章；校验期间数据库不可用也不能放行。状态读取后再发生撤回的在途响应、数据库主从延迟、公开文章编辑后旧正文仍在缓存/索引等问题不在此保证内。不给每次读取加行锁或长事务，也不声称墙钟意义的零延迟撤回。

验证集中于旧缓存命中/回源途中撤回、私密/草稿/软删/物理删除、状态读取失败、恢复发布、两种搜索模式的共同过滤及顺序保持，以及ES故障与真实空结果的区分。只运行修改链路与必要相邻回归，不运行无关全量测试。

## 第三个切片：私人内容的跨入口读取规则（BD-001）

2026-10-18 实施约定：复用现有文章筛选中的私人分类 ID 60/61 与三个私人标签（红红专属~、猫猫出没、w&p~）；任一命中即限制，普通标签不能抵消私人标签。原有两个指定邮箱账号可读取私人标记的 PUBLIC/未删文章，不能越过发布和删除状态。分类目录里的名称隐藏属于目录展示规则，暂不据此新增文章权限标记；目录名称与聚合计数的边界另行列出。

统一当前请求账号解析与数据库私人排除条件，覆盖首页、详情、MySQL/ES共同搜索出口、归档列表和数量、推荐、上下篇与分类/标签下文章。列表在分页/数量计算前筛选；详情缓存仍共享正文，但返回独立响应对象，上下篇在校验后按当前账号查询，不把个性化导航写回共享缓存。账号查询异常按普通权限处理，文章状态查询异常仍失败。

定向验证：匿名/普通/两个指定账号、混合标签、仅私人分类、PUBLIC/SECRET/DRAFT/删除、旧缓存命中、访问资格收回和恢复、请求交错下共享缓存导航隔离、归档数量及分页。使用隔离桩与实际 MyBatis 绑定 SQL 的内存执行验证，不连接真实业务库，不全仓测试。数据库快照之后的变更、旧正文版本、目录聚合与其他派生入口不冒充本切片已保证。

## 第四个切片：已有问答派生内容的撤回读取保护（BD-001）

2026-10-19 实施前核实：AiRagServiceImpl将向量检索结果直接加入模型上下文，引用也直接来自向量metadata；AiArticleServiceImpl写入articleId/title/url，但文章撤回不等待旧向量删除，问答缺少当前数据库可见性检查。此切片仅补已有内容派生出口，不扩展AI能力或评测平台。

业务不变量：生成前，仅使用当前请求有权读取且仍PUBLIC/未删的文章片段；未知/非法articleId不推断归属、不进入上下文。文章ID从实际向量metadata解析，批量复用selectVisibleArticleIds与ArticleAccessService，不信任向量中的发布/私人状态。生成后重新解析当前账号并批量校验所有实际使用的文章；任何来源已不可见则整段答案与引用不返回，不能仅删引用继续展示已混合的答案，也不自动重复付费生成。引用URL由已核验articleId构造，不照搬旧metadata URL。

失败与恢复：向量检索或权限查询失败返回明确业务失败，不冒充暂无内容；没有可用可见片段仍返回原暂无相关内容。来源撤回或账号资格收回后拒绝本次答案；用户重新提问且权限恢复时可正常执行。验证同一旧向量的撤回/恢复、混合可见与受限片段、重复片段、异常/缺失归属、模型执行期间撤回/资格变更及二次查库失败。全部用隔离VectorStore/ChatClient/Mapper，不调用真实模型或依赖。

承诺仅限两次可见性SQL快照对应阶段：首次SQL后才撤回的内容可能已提交模型，无法追回；第二次SQL后的在途撤回也不受零延迟保证。旧公开正文版本、模型幻觉、向量物理清理、后台任务投递与回写版本仍待接续。详情页承接不是本轮主线，保持待处理。
