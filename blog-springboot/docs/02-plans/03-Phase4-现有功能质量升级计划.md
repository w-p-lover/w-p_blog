# Phase4-现有功能质量升级计划

日期：2026-10-16。执行分支：`codex/blog-quality-daily`。

## 目标和范围

按用户本次授权，为 blog 建立持续日常质量提升。后端 `blog-springboot`、前台 `shoka-blog`、管理后台 `shoka-admin` 同属一个 Git 仓库；AI 学习项目和 homa-xxl-job 不在写入范围内。保持现有功能，优先完成度、内容呈现和正常/失败流程，不按功能数量衡量进度。

需求依据：用户 2026-10-16 的质量升级要求及 AGENTS.md；问题依据见 [质量审查与升级台账](../00-overview/05-质量审查与升级台账.md)。本计划由当前会话直接实施，遵循用户已授权的自主推进方式，不增加计划二次审批。

## 验证与收口

1. 仅针对新增状态逻辑检查筛选重置、一次查询、异步响应逆序、失败后重试、日期末日和事件清理。
2. 使用本地受控数据装载真实列表组件，浏览器检查桌面/手机布局、正常/空/失败状态和筛选操作；明确这不等同于真实后端联调。
3. 执行前台 `npm run build`；不无故运行全量后端、Redis、数据库或付费 AI 测试。
4. `git diff --check`，检查文档链接和变更文件，记录用户原有修改；不暂存或提交它们。

## 风险及后续顺序

当前 localhost:8080 的两个博客端点返回 404，不能认定该端口是本项目后端。真实内容质量、权限和部署结果均需真实运行证据。本轮不启动生产依赖、不改数据库、不调用付费模型、不部署、不自动合并或推送。

后续优先核实文章可见性的一致性，再处理搜索正确性、阅读失败恢复、分类/标签可达性、内容维护与部署入口。遇到确定的内容泄露或数据破坏缺陷优先于展示打磨。每轮完成一个可验收闭环；没有新证据或高价值问题时不制造改动。
