# 文档体系维护规范

## 1. 规范目标

这份文档用于约束 `docs` 目录的后续维护方式，避免项目继续开发后再次出现阶段命名混乱、总结文档散落、SQL 和部署说明混放、缓存与 AI 文档边界不清的问题。

后续每次开发新需求时，文档要和代码一样有清晰归属。开发前的计划、开发后的总结、数据库变更、部署说明、缓存方案和 AI 方案都应该放在固定位置，方便自己复盘，也方便面试时快速定位材料。

## 2. 分类规则

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `00-项目总览` | 项目定位、就业分析、长期路线、文档规范 | 单个功能的实现细节 |
| `01-架构设计` | 长期有效的整体架构、跨模块设计 | 阶段执行流水账 |
| `02-阶段计划` | 阶段开发前的目标、任务拆分、测试计划 | 开发完成后的改动总结 |
| `03-阶段总结` | 阶段完成后的升级内容、修改文件、测试结果 | 尚未执行的开发计划 |
| `04-缓存体系` | Redis、多级缓存、热榜、预热、限流、缓存治理 | 与缓存无关的普通业务总结 |
| `05-AI体系` | AI 能力地图、RAG、任务中心、Prompt、模型治理 | 普通前端页面说明 |
| `06-部署运维` | 本地启动、部署、配置中心、验收命令 | 建表 SQL 正文 |
| `07-数据库变更` | 建表 SQL、权限 SQL、字段迁移、数据修复 | 部署教程和业务设计 |
| `08-前端接入` | 前端页面接入计划、接口对接说明 | 后端内部服务设计 |
| `09-模板与脚本` | 环境变量模板、本地辅助脚本 | 业务代码和正式 SQL |
| `90-开发过程` | 临时执行计划、较长过程记录 | 最终总结文档 |
| `99-归档记录` | 不再维护但需要保留的历史文档 | 当前仍要阅读的主文档 |

## 3. 命名规则

目录命名使用两位序号加中文分类名：

```text
00-项目总览
01-架构设计
02-阶段计划
```

正式 Markdown 文档命名使用两位序号加中文语义名：

```text
01-就业项目分析.md
02-后端深度开发路线.md
03-Phase1-配置与测试环境总结.md
```

阶段文档统一使用 `PhaseN-主题`，不要混用 `Phase N`、`阶段N`、日期前缀和随意缩写。示例：

```text
01-Phase4-缓存治理体系计划.md
07-Phase4-缓存治理体系总结.md
```

SQL 文件也放入 `07-数据库变更`，使用序号加业务语义：

```text
03-Phase4-缓存治理建表与权限SQL.sql
04-文章热度快照表迁移SQL.sql
```

## 4. 阶段开发文档约定

每个阶段开始前，如果任务比较完整，应新增一份阶段计划，放入 `02-阶段计划`。计划至少包含：

- 阶段目标。
- 开发范围。
- 关键设计。
- 涉及模块。
- 测试策略。
- 验收标准。
- 风险和不做事项。

每个阶段完成后，必须新增或更新一份阶段总结，放入 `03-阶段总结`。总结至少包含：

- 阶段目标。
- 升级内容。
- 修改文件。
- 每个文件做了什么。
- 测试结果。
- 提交记录。
- 注意事项和后续建议。

如果阶段属于缓存或 AI 重点能力，还可以额外在 `04-缓存体系` 或 `05-AI体系` 补充专题文档。阶段总结仍然要保留在 `03-阶段总结`，不要只放专题目录。

## 5. 数据库变更约定

凡是涉及建表、加字段、权限初始化、数据修复、历史数据迁移，都放入 `07-数据库变更`。

数据库文档应该尽量做到可追溯：

- 文件名能看出业务目的。
- SQL 内部保留必要注释。
- 总结文档里引用对应 SQL 路径。
- 如果 SQL 已经在线上执行，总结文档里说明执行状态。

后续如果引入 Flyway 或 Liquibase，可以继续保留 `07-数据库变更` 作为人工说明目录，真正迁移脚本再放到框架要求的位置。

## 6. 路径引用约定

文档移动后必须同步更新旧路径引用。尤其注意这些情况：

- `docs/README.md` 中的导航链接。
- 阶段总结中引用的 SQL 文件。
- 路线文档中引用的设计文档。
- 缓存、AI、部署文档之间的互相跳转。

移动文档后建议搜索旧目录名：

```text
docs/01-架构设计
docs/02-部署运维
docs/03-缓存体系
docs/sql
```

如果搜索结果还指向不存在的旧路径，需要同步修正。

## 7. 当前整理后的重点边界

这次重构后，`01-架构设计` 只保留长期整体设计，不再塞阶段总结。阶段总结统一进入 `03-阶段总结`。

缓存专题从旧的 `03-缓存体系` 调整为 `04-缓存体系`，给 `02-阶段计划` 和 `03-阶段总结` 留出清晰位置。

部署说明从旧的 `02-部署运维` 调整为 `06-部署运维`，数据库 SQL 独立进入 `07-数据库变更`。

AI 相关内容新增 `05-AI体系` 作为专题入口，后续 RAG 质量评估、Prompt 版本治理、AI 指标治理、AI 任务中心增强都应优先沉淀到这里。
