# 限量技术活动前后台接入

2026-10-30/P6-03/A2。业务规则与API以[领域设计04](../01-architecture/04-限量技术活动报名设计.md)为准，逐文件职责和实际验证见[持续总结15第6—8节](../03-summaries/15-Phase6-限量活动报名开发总结.md)。

## 入口与操作

公开端`/activities`→`/activities/:id`，顶部动态菜单“技术活动”。匿名可看已发布活动，点击登录报名打开现有登录弹窗；登录后先查本人，再受理。正文/表单保留必要标签，没有用户ID/改库存/重报字段。窗口标北京时间，客户端时间/余量仅展示；PENDING是已受理，CONFIRMED才是成功。

后台沿数据库菜单生成`/activities`，组件为`/activity/index`。菜单权限activity:event:list，创建/编辑/发布/报名查看/失败恢复分别沿已有5个权限标识；不能用前端隐藏按钮代替后端校验。草稿创建和未来窗口配置、发布确认、按状态查报名、仅FAILED可恢复；已取消/售罄不重报。C菜单声明和角色授权分开，不自动给普通角色放权。

## 失败与接续

报名请求UUID按登录用户/活动持久保存后再发送，刷新/网络未知不换号；异常先查本人结果。串行轮询每次查询完成后3秒、最多20次，错误/预算后人工刷新，离开KeepAlive、登出/换账号和卸载停止或丢弃旧响应。终态无自动轮询，窗口结束仍查原PENDING。取消须确认不可重报，响应未知不自行补名额。

管理端保存失败保留表单；创建响应未知暂禁再次保存，关闭刷新核对。发布/失败恢复以当前事实为准，不把恢复已受理说成报名成功；报名抽屉不无限自动轮询。列表/详情错误和空数据分开，纯文本说明防止注入。窄屏保留主要操作，局部17px公开正文/15px管理字号，沿现有主题令牌适度加强颜色；无全站重设。
