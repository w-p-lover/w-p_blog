## 1. 环境与资源边界

使用项目已有`.env`及`config/application-private.yml`的数据库、RabbitMQ账户覆盖项；不读取或打印模型密钥，不启动Spring Boot、调度器、Canal或既有消费者；可选Java验证只启动新vhost内的隔离专用监听容器。执行前核对目标主机、数据库身份、账户权限及资源预算。没有本机Docker/MySQL不代表远程开发依赖不可用，应先核对配置和只读身份。

本次目标为既有远程依赖：MySQL 5.7.36/REPEATABLE-READ，RabbitMQ 3.9.11，Qdrant只读版本接口返回1.17.1。Redis 6.2.6仅验证认证PING和版本，不包含缓存故障验收。

每次生成唯一`blog_q4_<UUID>`作为独立MySQL库、RabbitMQ vhost、Qdrant集合名。MySQL只从博客库取得`t_ai_task`、`t_article`表结构，以`CREATE TABLE LIKE`复制至独立库；没有复制业务行，没有向业务表执行INSERT/UPDATE/DELETE/ALTER。独立库内仅插入合成文章/任务。RabbitMQ只在新vhost声明交换机、队列和当前测试账户的权限，不获取现有队列消息。Qdrant使用独立2维集合和固定合成向量，不调用Embedding。

共享服务器仍消耗少量连接/存储，独立命名空间不等于独占服务器。脚本不是负载工具；不得并行放大、循环压测或通过重启服务制造故障。它要求CREATE/DROP库、SHOW CREATE、InnoDB锁等待观察、创建/删除vhost及集合的权限；缺权限时不得改用业务表/队列替代。

脚本无`--execute`和明确`--expect-host`时拒绝运行；三个依赖配置主机必须匹配预期。HTTP管理接口沿用已有15672、Qdrant REST 6333，AMQP端口来自配置。只适用于当前连接方式，不自动关闭TLS/修改服务端安全配置。默认入口使用Python驱动和实际静态mapper XML。`--java`要求兼容的JAVA_HOME及PATH中可用的mvn，子进程运行唯一的AiTaskDependencyIntegrationTest，密码仅经环境变量传递；无该开关不启动JVM测试。Java用例默认跳过，只有明确的`BLOG_Q4_SCHEMA=blog_q4_<32位小写十六进制>`且JDBC路径与其完全一致才访问依赖，无配置回落到业务库。验收器还检查JUnit实际执行1项且无失败/错误/跳过，不能把默认跳过算通过。两种入口均不包含Qdrant Java客户端/完整应用整链。

开始即输出唯一资源名，结束在`logs/queue-acceptance/<运行名>.json`保存结果、查询计划和清理状态，不写密码、业务正文或模型请求。脚本在finally中删除本次创建的资源；异常或进程被强制结束后，应按输出的精确运行名检查残留，不能清理所有同前缀资源、清业务队列或重置任务。

## 3. 场景与实际证据

实际SQL不适配MySQL方言。两个连接验证任务行锁：发布先持锁时到期回收等待；回收先持锁时旧执行的FOR UPDATE等待后失去所有权。通过`INNODB_LOCK_WAITS`关联本次阻塞连接观察，不能仅用sleep或线程已启动推导数据库锁。

同事务发布/终态显式回滚、提交后新连接读取与重复认领、到期UNKNOWN/预算耗尽、两连接同时接续均验证。恢复扫描用100条不可接续任务和后续1条正常任务复现改前饥饿，修复后选中并恢复后者。该数据集的EXPLAIN为ALL/Using where/Using filesort；不据此声称扫描代价有界或索引高效，LIMIT只约束返回条数。

RabbitMQ真实mandatory无路由返回后，持久任务仍PENDING；恢复绑定、模拟投递预约到期后重投。同一任务发送两条持久消息，合成处理器在数据库提交结果后断开未ACK连接，新连接收到redelivered，重复消息不能再认领终态任务。第一次发布确认结果由测试刻意忽略，用于验证重复安全，未切断确认报文，不能称真实confirm丢包。没有停止broker或断服务器网络，未覆盖broker宕机/磁盘故障。

Qdrant先写10点并中断后续批次，再完成剩余3点、忽略其结果并重写两批，仍只有13点；新源写13点后旧源晚到写入仍为26个不同点。UUID算法对齐Java `UUID.nameUUIDFromBytes`的MD5/v3位。没有运行实际Embedding或RAG问答，不证明费用一次、读端权限过滤、持久化崩溃恢复，也未验证gRPC Java调用。

实际Java入口进一步运行生产AiTaskServiceImpl/AiTaskExecutionService/AiTaskDispatchService及AiArticleConsumer，采用真实MyBatis/SqlSessionTemplate、DataSourceTransactionManager/事务代理和专用AUTO工厂。只有AiArticleService是受控处理器，不构造模型/Embedding客户端。终态UPDATE被隔离触发器SIGNAL阻断时，文章摘要与任务状态一起回滚；移除触发器后正常完成。外层创建事务回滚不留任务和消息；提交后无路由返回保留PENDING，修复绑定经实际扫描重投，同任务2条消息只处理1次。该运行是程序化装配的隔离组件链路，不含完整配置装配、HTTP入口或跨JVM调度。
