# 个人技术博客成品边界

2026-11-27 按用户再次明确的要求修正：精简公开信息架构，保留个人兴趣功能与已经开发的 AI 架构。此前把这些模块从源码整体移除过度，本版恢复；不再将“源码存在”和“公开展示”混为同一件事。

## 当前产品

作者写作、保存草稿、发布/修改/撤回文章；读者浏览、检索、按分类/标签/归档查找内容，通过评论交流。说说保留配图、预览、点赞和评论。首页继续保留照片轮播、一言、推荐阅读、文章流、桌面宠物与按站点设置启用的音乐播放器；沿用已经调整过的排序、筛选和紧凑侧栏。

个人兴趣统一从“生活”（`/living`）进入：相册与照片、书架与阅读状态、音乐库与歌单、游戏、成长路线、天气、开源发现。原路由如 `/album`、`/book`、`/music`、`/steam`、`/life` 等继续有效，详情和相关后台管理恢复。顶部只增加一个“生活”入口，不堆叠全部兴趣导航。

原有配色、背景、波浪、过渡、悬停、点赞与回复保留；界面收敛不能成为删除个人兴趣或个人设计的理由。兴趣页继续沿用原有风格，不整体重做。

## AI 架构与公开边界

保留 Spring AI 模型客户端、RAG 检索、文章摘要/标签/向量流水线、任务实体/Mapper、事务后唤醒、持久任务扫描、认领租约、检查点、版本校验和指标。代码编译保留，正常 `dev`/`prod` 不创建模型或向量连接、不注册 AI controller、不扫描和消费 AI 任务。

显式增加 `ai` profile 后加载 `application-ai.yml`，供有后台权限的内部调用与维护。问答、写作辅助、索引重建均要求 `blog:article:update`；任务后台继续要求 `ai:task:list/retry`。普通读者不能通过直接请求绕过前台隐藏。公开前台不注册 `/ai-chat`、不挂载 AiWriterFloat，菜单也不出现 AI；旧页面组件与 API 源码保留但不接入读者端路由。

启用内部 AI 前仍需核实模型配置、Qdrant 和既有数据库契约，不自动执行迁移或调用付费模型。普通模式保存文章不创建 AI 任务，编辑时清除已过期的 AI 派生结果，保留后续内部重建依据。

活动报名、即时聊天、协作文档仍不进入当前产品；原实现完整保存在 `留存/简历对应完整版本`，本轮不恢复这些独立业务。留言管理与已有留言数据继续保留，独立弹幕页不接入。

## 数据与验证边界
