1. 首先读取台账的下一轮入口和最新阶段摘要，查看 git status 以及上轮之后相关路径的提交/工作区差异。无变化的事实直接复用，避免每天通读所有文档/记忆/仓库。

4. 阅读真实实现与调用方后做最小改动，遵守现有风格、编码和换行，必要注释使用简体中文。优先 Python 处理文件；不无关格式化或重构。
5. 测试按风险选最小有意义范围。新异步/状态逻辑可加针对性回归；仅文案/链接不写镜像测试。不为刷进展重跑无变化的全量测试、版本盘点、服务检查、哈希或付费评分。
6. UI 修改检查相关桌面/手机状态、空/失败/加载、键盘及主题；用受控数据时清楚标注，不当成真实后端联调或上线证据。
7. 更新台账原问题及对应阶段计划/总结，记录改了什么、各文件职责、实际命令及结果、未验证、提交或未提交状态、下一轮入口。遵守 docs/00 的文档分类，不每天新建整份相同报告。
8. 可创建本地普通提交，只提交本轮相关文件；不自动合并主分支、推送、部署、修改生产/真实业务数据、调用付费 AI 或启停已有服务。确需这些动作时先把本地可审阅结果完成，再根据现有授权判断。
