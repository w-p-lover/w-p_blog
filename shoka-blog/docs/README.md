## 命名规则

统一使用：

```text
YYYY-MM-DD-主题-文档类型.md
```

示例：

- `2026-04-28-首页杂志流-设计方案.md`
- `2026-04-28-首页杂志流-实施计划.md`
- `2026-05-07-前端升级-阶段总结.md`

约定：

- 日期统一放在最前面，方便按时间排序。
- 主题放中间，例如 `首页杂志流`、`书架升级`、`聊天室升级`。
- 类型放最后，例如 `设计方案`、`实施计划`、`阶段总结`、`总结与路线`。
- 不再在文件名里混用英文 slug、阶段编号和纯描述文本。

## 后续扩展建议

如果后面文档继续增加，优先按大主题建目录，而不是按文档类型建目录。

建议：

- 前端相关：继续放 `docs/前端升级/`，直到数量明显过多。
- 后端相关：可以新建 `docs/后端升级/`。
- 部署运维：可以新建 `docs/部署运维/`。
- 产品路线、复盘、长期规划：可以新建 `docs/项目规划/`。

只有当某个主题目录下文档超过十几份、确实难找时，再考虑在主题目录内部继续拆分。
