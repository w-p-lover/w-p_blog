# 音乐库收藏展示设计方案

## 1. 背景与目标

当前项目已经存在 `MusicPlayer` 组件，并通过 `meting-js` 接入网易云歌单播放能力。但现有能力更偏“播放器”，还不构成一个真正属于个人的音乐收藏库。

本次要做的不是重构全站，也不是做一个完整的音乐平台，而是新增一个可以长期填充、适合个人审美展示的“音乐收藏库”。它需要满足三个核心目标：

1. 以网易云为导入来源，尽量方便地把歌单或单曲收进来。
2. 支持用户慢慢补充内容，让每首歌变成“可阅读的收藏条目”，而不只是一个播放链接。
3. 在视觉上做出设计感和新意，整体像个人作品集、音乐档案馆或精选展陈页面。

## 2. 范围界定

### 2.1 本次要做

- 音乐库首页
- 歌单页
- 单曲详情页
- 收藏导入入口
- 基础搜索、筛选与排序
- 条目补充编辑能力
- 展示型视觉设计

### 2.2 本次不做

- 不做完整的在线播放平台
- 不做账号体系、付费、评论社区、关注订阅
- 不改全站通用样式、主题变量或公共布局
- 不把网易云功能整套搬进来

## 3. 产品形态

音乐库采用“导入 + 轻编辑 + 展示”的组合形态。

### 3.1 数据来源

优先支持以下两类来源：

- 网易云歌单 ID
- 网易云歌单链接

第一版只承诺支持公开可访问的歌单内容。导入时只需要拿到基础信息，后续用户可以继续补充内容；如果外部字段抓取不完整，允许降级为手动补齐。

### 3.2 用户可补充的内容

每首歌允许补充：

- 一句话备注
- 标签
- 收藏理由
- 心情或场景
- 评分或喜好等级
- 封面备注图或附加图片
- 来源说明

## 4. 视觉方向

这部分是本次功能的重点。

### 4.1 总体气质

音乐库要更像一个个人作品集，而不是工具页。建议采用“音乐档案馆 + 封面墙”的组合视觉：

- 首页有主视觉，不是直接堆表格或列表
- 卡片以封面为中心，辅以少量信息
- 页面信息层级清楚，但留白和节奏感更强
- 局部风格可以更有艺术感，整体仍保持克制

### 4.2 页面观感原则

- 以封面和标题形成第一视觉锚点
- 使用少量强调色，不把整个页面染成单一色调
- 允许轻微层叠、错位、悬浮、缩放等细节，增强“陈列感”
- 信息密度要适中，不能太空，也不能像后台表格
- 视觉新意要体现在排版、卡片层次和交互反馈上，而不是花哨动效堆叠

### 4.3 样式边界

必须遵守以下约束：

- 不修改全站通用样式文件
- 不改基础布局、导航、全局主题变量
- 音乐库相关样式只写在音乐库页面和专属组件中
- 如果需要统一视觉，只对音乐库内部组件做局部封装

## 5. 页面结构

### 5.1 音乐库首页

首页承担“入口 + 概览 + 精选展示”的作用。

建议布局：

1. 顶部主视觉区
   - 标题
   - 一句风格化描述
   - 总收藏数、歌单数、最近更新、最近导入等概览

2. 精选区
   - 最近收藏
   - 最近补充内容
   - 今日推荐或随机推荐

3. 封面墙区
   - 以卡片网格呈现歌单或单曲
   - 支持轻微大小变化或层级变化，形成展陈感

4. 筛选区
   - 歌单
   - 标签
   - 评分
   - 心情
   - 来源

### 5.2 歌单页

歌单页展示某一组收藏内容，强调“整理感”。

建议包含：

- 歌单封面或拼贴封面
- 歌单描述
- 歌单统计
- 歌曲列表或卡片列表切换
- 排序与筛选

### 5.3 单曲详情页

详情页是“内容慢慢长出来”的核心。

建议包含：

- 封面与基础信息
- 网易云来源信息
- 用户补充内容
- 标签与心情
- 相关收藏推荐
- 播放入口
- 附加图片或笔记区

## 6. 数据结构建议

建议把音乐条目分成“基础信息”和“扩展信息”两层。

### 6.1 基础字段

- `id`
- `title`
- `artist`
- `album`
- `cover`
- `songUrl` 或 `sourceId`
- `playlistId`
- `sourceType`
- `sourceUrl`
- `createdAt`
- `updatedAt`

### 6.2 扩展字段

- `note`
- `tags`
- `mood`
- `rating`
- `favoriteLevel`
- `summary`
- `extraImages`
- `isPinned`
- `displayOrder`

### 6.3 关系建议

音乐库最好支持以下层级：

- 1 个收藏库
- 多个歌单
- 每个歌单包含多首歌
- 每首歌可以单独补充内容

这样既能从网易云导入歌单，也能后续手动微调单曲内容。

## 7. 导入流程

### 7.1 导入方式

推荐先做最简单的两种：

- 粘贴网易云歌单链接
- 输入歌单 ID

### 7.2 导入步骤

1. 用户输入歌单链接或 ID
2. 系统解析来源
3. 拉取基础歌曲信息
4. 生成本地收藏条目
5. 允许用户在导入后立刻补内容

### 7.3 导入策略

优先保证“能导进来”，再保证“信息尽量完整”。

如果某些字段无法自动获取：

- 先保留基础信息
- 允许用户手动补齐
- 在详情页提示哪些信息来自网易云，哪些是个人补充

## 8. 交互设计

### 8.1 列表与卡片

- 默认展示卡片墙，突出封面与视觉效果
- 允许切换到紧凑列表，方便批量浏览
- 卡片 hover 时强调封面、标题和状态，不做复杂跳动

### 8.2 筛选与排序

支持基础筛选：

- 标签
- 歌单
- 评分
- 心情
- 最近更新

支持基础排序：

- 最新收藏
- 最近更新
- 评分最高
- 标题字母序

### 8.3 编辑体验

编辑不做重表单，保持轻量：

- 详情页内可快速编辑
- 标题、标签、备注可直接修改
- 复杂信息放到展开区域

## 9. 与现有系统的集成方式

### 9.1 路由集成

新增独立音乐库路由，和现有文章、书架、相册、实验室并列，不挤占已有页面职责。

### 9.2 播放器集成

现有 `MusicPlayer` 继续保留，作为页面下方或侧边的轻量播放能力。

新音乐库页面不要依赖播放器才能成立，播放器只是辅助，不是核心。

### 9.3 样式隔离

音乐库相关样式单独放在自己的视图目录和组件目录中，避免污染全局样式系统。

## 10. 错误处理与降级

### 10.1 导入失败

如果网易云导入失败：

- 提示当前歌单无法读取
- 保留已导入的本地数据
- 允许用户稍后重试

### 10.2 字段缺失

如果缺少封面、简介或来源信息：

- 使用占位封面
- 使用简短默认文案
- 不阻断收藏条目显示

### 10.3 网络不可用

如果外部来源不可用：

- 页面仍能浏览本地已保存的收藏
- 播放能力可单独降级
- 内容展示不依赖实时外部接口

## 11. 测试与验收

本次重点验收“看起来是否成立”和“功能是否清楚”，而不是做大量自动化测试。

### 11.1 视觉验收

- 首屏有没有主视觉和层次
- 卡片墙是否有设计感
- 详情页是否像收藏档案，而不是普通表单
- 样式是否没有污染全站

### 11.2 功能验收

- 是否能导入网易云歌单
- 是否能看到收藏条目
- 是否能补充内容
- 是否能正常筛选和进入详情页

### 11.3 稳定性验收

- 页面没有明显错位
- 空状态可用
- 导入失败时能降级展示

## 12. 交付原则

1. 先把视觉和信息结构做对。
2. 再把导入和编辑做顺。
3. 不动全站通用样式。
4. 让这个功能可以慢慢长大，而不是一次性做满。
